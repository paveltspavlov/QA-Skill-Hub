# Form Builder

## Procedure
1. List fields, data types, required/optional status, validation rules, conditional logic, and submit/cancel behavior.
2. Inspect the project's form library, component library, and error-message conventions; do not add a stack without approval.
3. Associate labels and instructions, expose errors programmatically, preserve keyboard/focus behavior, and avoid color-only feedback.
4. Cover valid, invalid, boundary, empty, server-error, loading, and repeat-submit states as appropriate.
5. Test interactions and assistive-technology semantics where possible; separate automated findings from manual checks.

## Output
An accessible form component or specification with validation and interaction tests.
